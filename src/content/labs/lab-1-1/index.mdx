## Welcome

Welcome to **TCM Security Academy's Introduction to Windows Forensics**. This first lab is the only one with any real setup. You will install a hypervisor on your host, build a clean Windows 11 virtual machine, attach the course ISO containing the class files, and run the setup script.

By the end of this lab you will have a snapshot of a fully configured **course VM**. The majority of labs in this course are performed inside that VM. Treat your host machine purely as a place to run the hypervisor.

<Callout type="note" title="A note on the lab workbook">
  You are most likely reading this lab on your host machine, before the course VM exists. Once the VM is running, the setup script installs a local copy of this same workbook inside it, and a desktop shortcut opens it in the VM's browser.
</Callout>

## What you will need

Make sure your host machine meets the following minimums before you start:

- A 64-bit **x86-64** host operating system. Windows 10 or 11, macOS 12 or newer on Intel, or a recent Linux distribution will all work.
- At least **16 GB of RAM** on the host. It is recommended to give the VM 8 GB and leave at least 8 GB free for the host itself.
- At least **4 free CPU cores** the hypervisor can allocate to the VM.
- At least **120 GB of free disk space** on a fast local drive. It is recommended to give the VM a 100 GB disk. The Windows 11 install + tools take up around 25 GB, and you will collect memory images and disk images during the labs.
- A reliable internet connection. You will use it to download the Windows 11 Eval ISO, the course ISO, and a few additional tools during setup.

<Callout type="warning" title="Note for Apple Silicon users (M1/M2/M3/M4)">
  This course is built around **x86-64** Windows tooling. Apple Silicon Macs run ARM and rely on emulation (via Parallels or VMware Fusion with Windows 11 ARM) to run the lab environment, which can introduce compatibility issues with some forensic tools. An x86-64 Windows or Linux host is strongly recommended.
</Callout>

You will also need accounts and tools:

- A valid email address. Microsoft requires one to register and download the Windows 11 Eval ISO.
- Access to the **TCM Security Academy course portal**, where the course ISO is hosted.
- A **hypervisor**. VMware Workstation Pro on Windows or Linux, and VMware Fusion Pro on macOS, are both free for personal use as of November 2024<Cite id="vmware-personal-use" /> and are the recommended option for this course. [VirtualBox](https://www.virtualbox.org/wiki/Downloads)<Cite id="virtualbox" /> will also work as a fallback.

## Step 1: Install your hypervisor

If you do not already have VMware installed, download and install it now.

- **Windows or Linux:** install **VMware Workstation Pro** from the [Broadcom download portal](https://support.broadcom.com/group/ecx/free-downloads)<Cite id="broadcom-downloads" />. Choose the Workstation Pro option, not Workstation Player.
- **macOS:** install **VMware Fusion Pro** from the same portal<Cite id="broadcom-downloads" />.

Both products are free for personal use, but you will need to register a Broadcom account to access the installer. Run the installer with the default options. If you are prompted for a license key, choose the personal use option rather than entering a key.

<Callout type="note" title="VirtualBox Fallback">
  If you cannot install VMware on your host, VirtualBox will work as a fallback. This lab's instructions assume VMware. You will need to translate the hypervisor-specific steps yourself.
</Callout>

## Step 2: Download the Windows 11 Enterprise Evaluation ISO

Go to the [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise)<Cite id="win11-eval" />, fill out the **Register for your free trial today** form, and download the **64-bit ISO** of Windows 11 Enterprise. It is approximately 6 GB.

<Callout type="note" title="About the 90-day clock">
  The Eval ISO gives you 90 days of activation. That is more than enough for this course. If you exceed it, Windows will start warning you and eventually limit functionality, but you can simply build a new VM from the same ISO and rerun this lab.
</Callout>

Save the ISO somewhere on a fast local drive. Do not save it inside a folder synchronized by OneDrive, iCloud Drive, Dropbox, or Google Drive. Cloud sync clients can lock or rewrite large files in the background and corrupt them mid-transfer.

## Step 3: Download the course ISO

Sign in to the TCM Security Academy course portal and locate the **Introduction to Windows Forensics** course materials. Download the **course ISO**. It is approximately **5 GB**.

You do **not** need to extract this ISO or mount it on your host. You will be attaching it directly to the VM in Step 8, after the VM is built. Save it to the same place as the Windows 11 Eval ISO.

## Step 4: Create the VM

Launch VMware. From the **File** menu, choose **New Virtual Machine** and walk through the wizard:

1. **Configuration type:** choose **Custom** so you can pin the disk size and CPU/RAM yourself.
2. **Hardware compatibility:** pick the latest version offered.
3. **Guest operating system installation:** choose **Installer disc image (ISO)** and browse to the **Windows 11 Eval ISO** you downloaded in Step 2. (Not the course ISO. That comes later.)
4. **Guest operating system:** Microsoft Windows. Version: **Windows 11 x64**.
5. **Virtual machine name and location:** call it something like `tcm-windows-forensics`. Save it on a fast local drive with plenty of free space, in a folder that is **not** synced by OneDrive, iCloud Drive, Dropbox, or Google Drive.
6. **Processors:** 1 processor, 4 cores per processor (4 vCPUs total).
7. **Memory:** **8192 MB** (8 GB).
8. **Network:** **NAT**. The VM gets internet through the host.
9. **I/O controller, disk, virtual disk type:** accept the defaults VMware suggests for Windows 11.
10. **Disk capacity:** **100 GB**. Choose **Store virtual disk as a single file**.

Before finishing the wizard, click **Customize Hardware** and confirm two things:

- **Encryption / Secure Boot / TPM:** Windows 11 requires Secure Boot and TPM 2.0. VMware Workstation Pro will add both automatically for a Windows 11 guest. If it prompts you to set a VM encryption password to enable TPM, do so and write the password down somewhere you can find it. Losing it means you cannot boot this VM again.
- **CD/DVD drive:** confirm it is pointing at the Windows 11 Eval ISO and that **Connect at power on** is checked.

Finish the wizard, but *do not boot the VM yet*.

## Step 5: Install Windows 11

Power on the VM. The Windows installer will boot from the Eval ISO. Walk through it slowly. The answers below are picked to keep every student's VM consistent so the rest of the labs behave the same way.

1. **Language to install:** English (United States).
2. **Time and currency format:** English (United States).
3. **Keyboard or input method:** US.
4. Click **Install now**.
5. **Activate Windows:** click **I don't have a product key**. The Eval ISO does not need one.
6. **Operating system:** **Windows 11 Enterprise** is the only option.
7. **License terms:** accept.
8. **Which type of installation:** **Custom: Install Windows only**.
9. **Where to install:** select the only disk listed and click **Next**. Windows will partition and format it.

Windows will copy files, reboot a few times, and eventually arrive at the **out-of-box experience (OOBE)** with the country picker. Continue with these answers:

1. **Country or region:** United States.
2. **Keyboard layout:** US. **Skip** the second keyboard prompt.
3. **Name your device:** anything you like. `tcm-vm` is a fine default.
4. **Sign-in options:** the Enterprise Eval ISO will let you create a **local account** directly. Choose **Domain join instead** or **Sign-in options → Offline account**, depending on which prompt your build of the ISO shows. You want the path that says "create a local user."
5. **User name:** anything you like. `examiner` is the placeholder shown in later screenshots. The course does not require a specific username.
6. **Password:** anything you like. Pick something you can remember; the VM is disposable but you will type the password every time you sign in.
7. **Security questions:** answer however you like.
8. **Privacy settings:** turn **all of them off**. Location, Find my device, Diagnostic data, Inking and typing, Tailored experiences, Advertising ID. None of them apply to a forensic lab VM.

After the privacy screen Windows will finish setting up your profile. The first sign-in usually takes a minute or two.

<Callout type="tip" title="If Windows refuses to create a local account">
  Some Windows 11 builds make the local-account path hard to find. If the OOBE will not let you create a local user, press **Shift+F10** on the Microsoft account screen to open a Command Prompt, run `oobe\bypassnro`, and the VM will reboot back into OOBE with a local-account option available. On Windows 11 24H2 and later, run `start ms-cxh:localonly` instead at the same prompt.
</Callout>

## Step 6: Install VMware Tools

Once you are on the Windows desktop, install **VMware Tools** so clipboard sharing, screen resizing, and drag-and-drop between host and VM all work.

From the VMware menu bar, choose **VM → Install VMware Tools**. Windows will mount a virtual DVD with the VMware Tools installer. Open File Explorer, browse to the new DVD drive, and run `setup64.exe`. Accept the defaults. Reboot when prompted.

After the reboot, your VMware window should resize cleanly when you drag its corners. If it does not, VMware Tools did not install correctly. Re-run the installer.

## Step 7: Take a `fresh-install` snapshot

Before you go any further, take a snapshot of the clean Windows 11 install. If anything goes wrong from here on, you can roll back to this snapshot instead of redoing Steps 2 through 6.

1. Right-click the VM in your VMware library.
2. Choose **Snapshot → Take Snapshot**.
3. Name it `fresh-install` and click **Take Snapshot**.

## Step 8: Attach the course ISO to the VM

Now swap the CD/DVD drive from the Windows installer to the course ISO. With the VM running:

1. From the VMware menu bar, choose **VM → Settings**.
2. In the hardware list, select **CD/DVD (SATA)**.
3. On the right, choose **Use ISO image file**, browse to the **course ISO**, and click **OK**.
4. Make sure **Connected** and **Connect at power on** are both checked.
5. Click **OK** to apply.

Inside Windows, the ISO will appear as a new drive letter, usually `D:` or `E:`. Open File Explorer to confirm it. You should see `setup.ps1`, `verify-setup.ps1`, and a couple of folders.

## Step 9: Run `setup.ps1`

`setup.ps1` does the heavy lifting: it configures the VM and installs everything the rest of the course needs. It takes 10 to 15 minutes.

1. Click **Start**, type `PowerShell`, right-click **Windows PowerShell**, and choose **Run as administrator**.
2. Confirm the User Account Control prompt. The window title should read **Administrator: Windows PowerShell**.
3. Run the two commands below, replacing `D:` with whatever drive letter the course ISO mounted on:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
& 'D:\setup.ps1'
```

The first command lets the script run in this shell session only<Cite id="set-execution-policy" />. It does not change any system-wide policy.

The script prints a header for each step and a green `[OK]` line for every item that succeeds. Stay on this terminal and watch it scroll. If anything fails, the script keeps going and lists the failures at the end, along with the path to the log file (`C:\Forensics\setup.log`).

<Callout type="tip" title="The script is safe to re-run">
  If you hit a transient error like a flaky download, fix the underlying issue (re-attach the ISO, reconnect the network, confirm you are running as Administrator) and re-run the same command. The script checks every step's state before acting, so it will only redo what is missing.
</Callout>

When the script finishes, it prints a short checklist of any additional tools that need to be installed by hand. Those are covered in Step 10.

## Step 10: Install the manual tools

A handful of tools are free but their license terms forbid TCM from redistributing them on the course ISO. You will need to download and install each one yourself. Each is a short download and a default-options install.

### FTK Imager

From [Exterro](https://www.exterro.com/digital-forensics-software/ftk-imager)<Cite id="ftk-imager" />. Free download; an email registration is required. Run the installer with the default options.

### Magnet Encrypted Disk Detector (EDD)

From [Magnet Forensics](https://www.magnetforensics.com/resources/encrypted-disk-detector/)<Cite id="magnet-edd" />. Free with email registration. Default options.

### Magnet DumpIt for Windows

From [Magnet Forensics](https://www.magnetforensics.com/resources/magnet-dumpit-for-windows/)<Cite id="dumpit" />. Free with email registration. Default options.

## Step 11: Run `verify-setup.ps1`

`verify-setup.ps1` does a read-only sweep to confirm everything the rest of the course needs is in place.

Back in the same elevated PowerShell:

```powershell
& 'D:\verify-setup.ps1'
```

(Replace `D:` with your course ISO drive letter, same as in Step 9.)

Every line should print `[OK]` in green. If anything prints `[MISSING]`, fix the underlying issue and re-run the verifier.

## Step 12: Take a `course-ready` snapshot

Once `verify-setup.ps1` reports all green, take a second snapshot. This is the state you will roll back to whenever a later lab leaves your VM in a state you cannot recover.

1. Right-click the VM in your VMware library.
2. Choose **Snapshot → Take Snapshot**.
3. Name it `course-ready` and click **Take Snapshot**.

You are done with Lab 1.1.

## Troubleshooting

### `setup.ps1` exits immediately with "could not find the course ISO"

The script walks every drive letter looking for the marker file `tcm-windows-forensics.marker` on its root. If it cannot find one, the ISO is not attached, or it is attached but not "connected."

1. From the VMware menu bar, choose **VM → Settings → CD/DVD (SATA)** and confirm:
   - The ISO image path points at your course ISO.
   - **Connected** is checked.
   - **Connect at power on** is checked.
2. In File Explorer inside the VM, confirm you see a new drive letter with `setup.ps1` on it.
3. Re-run the script.

### PowerShell complains "the script is not digitally signed"

You forgot the first line in Step 9. Run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in the same PowerShell window<Cite id="set-execution-policy" /> and re-run the setup command. The bypass only applies to that one shell session and is dropped when you close it.

### "VMware Workstation and Device/Credential Guard are not compatible"

Windows 10 and 11 hosts ship with a security feature called **Credential Guard** that uses the same virtualization extensions VMware needs. When Credential Guard is on, VMware will refuse to power on the VM and will display the error above.

Microsoft publishes a tool called the [Device Guard and Credential Guard hardware readiness tool](https://www.microsoft.com/en-us/download/details.aspx?id=53337)<Cite id="dg-readiness" /> that can disable Credential Guard. Download it from the Microsoft download center, run it from an elevated PowerShell prompt with the `-Disable` flag, and reboot. After the reboot VMware should power on the VM normally.

### The VM is unbearably slow on a Windows host

Windows 10 and 11 sometimes throttle VMware's main process under power management, which makes the VM crawl even on fast hardware. You can exclude VMware from power throttling with a single elevated [`powercfg`](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options)<Cite id="powercfg-throttling" /> command on the **host**, not the VM:

```powershell
powercfg /powerthrottling disable /path "C:\Program Files (x86)\VMware\VMware Workstation\x64\vmware-vmx.exe"
```

Reboot the host after running it. The path above assumes a default install location; adjust it if you installed VMware somewhere else.

### Drag and drop or shared folders do not work between the host and the VM

These features are provided by VMware Tools. If they are not working, either VMware Tools is not installed (re-run Step 6) or the **Shared Folders** option is not enabled. Power the VM off, open its settings in VMware, enable Shared Folders, and power the VM back on.

### The lab workbook is not loading at `http://localhost:5173`

Setup registers a scheduled task that starts the workbook dev server at logon. The task does not run until you sign out and back in for the first time. Either sign out / sign in, or open a regular (not elevated) PowerShell and run:

```powershell
cd C:\Forensics\Workbook
npm run dev
```

Leave that terminal open and refresh `http://localhost:5173` in your browser.
