## Welcome

Welcome to **TCM Security Academy's Introduction to Windows Forensics**. This first lab is the only one with any major setup. You will install a hypervisor on your host, build a clean Windows 11 virtual machine, attach the two course ISOs, and run their setup scripts.

By the end of this lab you will have a snapshot of a fully configured **course VM**. The majority of labs in this course are performed inside that VM. Treat your host machine purely as a place to run the hypervisor.

<Callout type="note" title="A note on the lab workbook">
  You are most likely reading this lab on your host machine, before the course VM exists. Once the VM is fully set up, an electronic copy of this same workbook runs inside it and a desktop shortcut opens it in the VM's browser.
</Callout>

## What you will need

Make sure your host machine meets the following minimums before you start:

- A 64-bit **x86-64** host operating system. Windows 10 or 11, macOS 12 or newer on Intel, or a recent Linux distribution will all work.
- At least **16 GB of RAM** on the host. It is recommended to give the VM 8 GB and leave at least 8 GB free for the host itself.
- At least **4 free CPU cores** the hypervisor can allocate to the VM.
- At least **120 GB of free disk space** on a fast local drive. It is recommended to give the VM a 100 GB disk. The Windows 11 install + tools take up around 25 GB, and you will collect memory images and disk images during the labs.
- A reliable internet connection. You will use it to download the Windows 11 Eval ISO, the course ISO, and a few additional tools during setup.

<Callout type="warning" title="Note for Apple Silicon users (M1/M2/M3/M4)">
  This course is built around **x86-64** Windows tooling. Apple Silicon Macs run ARM and rely on emulation (via Parallels or VMware Fusion with Windows 11 ARM) to run the lab environment, which can introduce compatibility issues with some forensic tools. An x86-64 Windows or Linux host is strongly recommended.
</Callout>

You will also need accounts and tools:

- A valid email address. Microsoft requires one to register and download the Windows 11 Eval ISO.
- Access to the **TCM Security Academy course portal**, where the *course ISOs* are hosted.
- A **hypervisor**. VMware Workstation Pro on Windows or Linux, and VMware Fusion Pro on macOS, are both free for personal use as of November 2024<Cite id="vmware-personal-use" /> and are the recommended option for this course. [VirtualBox](https://www.virtualbox.org/wiki/Downloads)<Cite id="virtualbox" /> will also work as a fallback.

## Step 1: Install your hypervisor

If you do not already have VMware installed, download and install it now.

- **Windows or Linux:** install **VMware Workstation Pro** from the [Broadcom download portal](https://support.broadcom.com/group/ecx/free-downloads)<Cite id="broadcom-downloads" />. Choose the Workstation Pro option, not Workstation Player.
- **macOS:** install **VMware Fusion Pro** from the same portal<Cite id="broadcom-downloads" />.

Both products are free for personal use, but you will need to register a Broadcom account to access the installer. Run the installer with the default options. If you are prompted for a license key, choose the personal use option rather than entering a key.

<Callout type="note" title="VirtualBox Fallback">
  If you cannot install VMware on your host, VirtualBox will work as a fallback. This lab's instructions assume VMware. You will need to translate the hypervisor-specific steps yourself.
</Callout>

## Step 2: Download the Windows 11 Enterprise Evaluation ISO

Go to the [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise)<Cite id="win11-eval" />, fill out the **Register for your free trial today** form, and download the **64-bit ISO** of Windows 11 Enterprise. It is approximately 6 GB.

<Callout type="note" title="About the 90-day clock">
  The Eval ISO gives you 90 days of activation. That is more than enough for this course. If you exceed it, Windows will start warning you and eventually limit functionality, but you can simply build a new VM from the same ISO and rerun this lab.
</Callout>

Save the ISO somewhere on a fast local drive. Do not save it inside a folder synchronized by OneDrive, iCloud Drive, Dropbox, or Google Drive. Cloud sync clients can lock or rewrite large files in the background and corrupt them mid-transfer.

## Step 3: Download the course ISOs

Sign in to the TCM Security Academy course portal and locate the **Introduction to Windows Forensics** course materials. There are **two** additional ISOs to download:

- **`WF_A.iso`** is the forensic workstation setup. It installs every tool and tweak for the Windows forensics curriculum. Approximately **3 GB**.
- **`WF_B.iso`** contains the course exercises and the lab workbook.

Each ISO ships **inside a password-protected `.zip`**. Extract both zips on your host so the `.iso` files sit alongside the Windows 11 Eval ISO. You do **not** need to mount either ISO on your host after extraction. You will attach them directly to the VM, one at a time, in later steps.

**The password for both archives is:** `forensics`

Launch VMware. From the **File** menu, choose **New Virtual Machine** and walk through the wizard:

1. **Configuration type:** choose **Typical (recommended)**.
2. **Guest operating system installation:** choose **Installer disc image (ISO)** and browse to the **Windows 11 Eval ISO** you downloaded in Step 2. (Not the course ISO. That comes later).
    - Confirm Microsoft Windows / **Windows 11 x64** (VMware auto-detects this from the ISO in most cases).
3. **Virtual machine name and location:** call it something like `tcm-windows-forensics`. Save it on a fast local drive with plenty of free space, in a folder that is **not** synced by OneDrive, iCloud Drive, Dropbox, or Google Drive.
4. **Encryption Information:** Windows 11 requires TPM 2.0, and VMware can only emulate a TPM on an encrypted VM. Choose **"Only the files needed to support a TPM are encrypted"** (the recommended option).

- **Memory:** **8192 MB** (8 GB).
- **Processors:** 1 processor, 4 cores per processor (4 vCPUs total).
- **CD/DVD drive:** confirm it is pointing at the Windows 11 Eval ISO and that **Connect at power on** is checked.
- **Network Adapter:** **NAT**. The VM gets internet through the host.

## Step 5: Install Windows 11

Power on the VM. The Windows installer will boot from the Eval ISO. Walk through the prompts as follows:

1. **Select language settings.**
    - **Language to install:** pick whatever suits your needs.
    - **Time and currency format:** pick whatever suits your needs.
2. **Select keyboard settings.**
    - **Keyboard or input method:** pick whatever suits your needs.
3. **Select setup option:** **Install Windows 11**.
    - Tick the **I agree everything will be deleted including files, apps, and settings** confirmation.
4. **Accept the license terms.**
5. **Select location to install Windows 11:** select the only disk listed and click **Next**. Windows will partition and format it.
6. **Ready to install:** click **Install**.

The install will take several minutes. The installer shows a progress percentage and reboots the VM a couple of times on its own.

<Figure
  src={windowsInstall1}
  alt="Windows 11 installer screen reading Installing Windows 11. Your PC will restart several times. This might take a while."
  caption="The installer's progress screen. The VM will likely reboot on its own a few times."
  width={500}
/>

Once it finishes, the VM arrives at the **out-of-box experience (OOBE)** with the country picker. Walk through the prompts as follows:

1. **Is this the right country or region?** pick whatever suits your needs.
2. **Is this the right keyboard layout or input method?** pick whatever suits your needs.
3. **Want to add a second keyboard layout?** add another layout or click **Skip**, your choice.
4. The installer will likely check for updates at this point and may apply a small batch before continuing. Let it run.
5. **Let's set things up for your work or school:** click **Sign-in options** in the lower left.
    - Choose **Domain join instead**. This is the path that creates a local user instead of forcing a Microsoft account.
6. **Who's going to use this device?**
    - **Enter your name (username):** `tcm`
    - **Enter a password:** Pick something you can remember. You will type it every time you sign in to the VM.
    - **Confirm password.**
    - **Security questions:** answer however you like.
7. **Choose privacy settings for your device:** turn **all of them off**.
8. Windows will **download and install pending updates**, then finish setting up your profile and drop you on the desktop. The first sign-in usually takes quite a few minutes.

<Callout type="tip" title="If Windows refuses to create a local account">
  Some Windows 11 builds make the local-account path hard to find. If the OOBE will not let you create a local user, press **Shift+F10** on the Microsoft account screen to open a Command Prompt, run `oobe\bypassnro`, and the VM will reboot back into OOBE with a local-account option available. On Windows 11 24H2 and later, run `start ms-cxh:localonly` instead at the same prompt.
</Callout>

## Step 9: Run `setup_a.ps1`

The `setup_a.ps1` script will configure the VM and install everything the rest of the course needs. It can take around 10 to 15 minutes, sometimes much longer, depending on network bandwidth.

1. Click **Start**, type `PowerShell`, right-click **Windows PowerShell**, and choose **Run as administrator**.
2. Confirm the User Account Control prompt. The window title should read **Administrator: Windows PowerShell**.
3. Run the two commands below, replacing `D:` with whatever drive letter the course ISO mounted on:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& 'D:\setup_a.ps1'
```

The first command bypasses PowerShell's script-execution policy for the current process<Cite id="set-execution-policy" />, allowing the `setup_a.ps1` to run.

<Figure
  src={powershell1}
  alt="Windows Start menu search results for PowerShell, with Windows PowerShell selected and a right-click context menu showing Run as administrator highlighted"
  caption="Open the Start menu and start typing PowerShell, then right-click Windows PowerShell and choose Run as administrator."
  width={600}
/>

Early on, the script will ask whether to **auto-fetch** the manual tools. Several tools are distributed outside the course ISO. The script attempts to download each one directly from the vendor's public CDN. If any downloads fail, the script will provide a reference list of the remaining tools that require manual installation.

The script prints a header for each step and a green `[OK]` line for every item that succeeds. Stay on this terminal and watch it scroll. If anything fails, the script keeps going and lists the failures at the end, along with the path to the log file (`C:\Forensics\setup.log`).

<Figure
  src={setupA2}
  alt="Administrator PowerShell window showing setup_a.ps1 mid-run, with cyan section headers and green [OK] lines streaming past"
  caption="setup_a.ps1 partway through its run. The script logs each step as it works through the tool list."
  width={800}
/>

**Note:** A few `[SKIP]` or `[FAIL]` lines throughout the run are normal. `setup_a.ps1` installs the full arsenal of tools used across the entire Windows forensics learning path and not every course uses every tool. If you care about a specific item or require it for a future lab, try re-running the script or alternatively fetch the tool by hand.

When the script finishes, it prints a short checklist of any additional tools that need to be installed by hand. Those are covered in a later section.

## Troubleshooting

### The `setup_a.ps1` script exits immediately with "could not find the course ISO"

The ISO is likely not attached, corrupt, or it is attached but not "connected."

1. From the VMware menu bar, choose **VM → Settings → CD/DVD (SATA)** and confirm:
   - The ISO image path points at your course ISO.
   - **Connected** is checked.
   - **Connect at power on** is checked.
2. In File Explorer inside the VM, confirm you see a new drive letter with `setup_a.ps1` on it.
3. Re-run the script.

### PowerShell complains "the script is not digitally signed"

You forgot the first line in Step 9. Run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force` in the same PowerShell window<Cite id="set-execution-policy" /> and re-run the setup command. The bypass only applies to that one shell session and is dropped when you close it.

### "VMware Workstation and Device/Credential Guard are not compatible"

Windows 10 and 11 hosts ship with a security feature called **Credential Guard** that uses the same virtualization extensions VMware needs. When Credential Guard is on, VMware will refuse to power on the VM and will display the error above.

Microsoft publishes a tool called the [Device Guard and Credential Guard hardware readiness tool](https://www.microsoft.com/en-us/download/details.aspx?id=53337)<Cite id="dg-readiness" /> that can disable Credential Guard. Download it from the Microsoft download center, run it from an elevated PowerShell prompt with the `-Disable` flag, and reboot. After the reboot VMware should power on the VM normally.

### The VM is unbearably slow on a Windows host

Windows 10 and 11 sometimes throttle VMware's main process under power management, which makes the VM crawl even on fast hardware. You can exclude VMware from power throttling with a single elevated [`powercfg`](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options)<Cite id="powercfg-throttling" /> command on the **host**, not the VM:

```powershell
powercfg /powerthrottling disable /path "C:\Program Files (x86)\VMware\VMware Workstation\x64\vmware-vmx.exe"
```

Reboot the host after running it. The path above assumes a default install location, so ensure to adjust it if you installed VMware somewhere else.

### The lab workbook is not loading at `http://localhost:5173`

The workbook dev server is started by **`setup_b.ps1`**. If `localhost:5173` is not responding:

1. Confirm `setup_b.ps1` finished without listing any failures. If `npm install` failed mid-run, re-run the script.
2. Wait 20-30 seconds after the script completes. Vite needs a moment to bind the port the first time.
3. Open Task Scheduler and confirm the **TCMWorkbookDevServer** task exists and ran. Right-click it and choose **Run** if it has not started.

If none of that helps, open a regular (not elevated) PowerShell and run the server by hand:

```powershell
cd C:\Forensics\Workbook\iwf
npm run dev
```

Leave that terminal open and refresh `http://localhost:5173` in your browser.
